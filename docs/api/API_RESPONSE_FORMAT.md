# 📋 Формат ответов API для работы с apiMessages

## 🎯 Общие правила

Система обработки сообщений (`apiMessages.js`) поддерживает различные форматы ответов от сервера и использует приоритетную систему определения сообщений для пользователя.

---

## ✅ Успешные ответы (статус 200-299)

### Вариант 1: Минимальный ответ
```json
{
  "user_type": "teacher",
  "username": "ivan@example.com"
}
```
**Сообщение пользователю:** Будет использован дефолтный текст из конфигурации (`apiMessages.login.success`)

---

### Вариант 2: С кастомным сообщением
```json
{
  "user_type": "teacher",
  "username": "ivan@example.com",
  "message": "Добро пожаловать обратно, Иван!"
}
```
**Сообщение пользователю:** `"Добро пожаловать обратно, Иван!"`

---

### Вариант 3: С кодом (для специальных случаев)
```json
{
  "user_type": "teacher",
  "username": "ivan@example.com",
  "code": "first_login",
  "message": "Это ваш первый вход в систему"
}
```
**Сообщение пользователю:** Если код `first_login` есть в конфигурации - используется он, иначе - `message`

---

## ❌ Ответы с ошибками (статус 400+)

### Вариант 1: Только HTTP статус (минимум)
```json
{}
```
**HTTP статус:** `401`  
**Сообщение пользователю:** Берётся из `apiMessages.login.byStatus[401]` → `"Неверный логин или пароль"`

---

### Вариант 2: С кодом ошибки (РЕКОМЕНДУЕТСЯ)
```json
{
  "code": "invalid_credentials"
}
```
**HTTP статус:** `401`  
**Сообщение пользователю:** Берётся из `apiMessages.login.invalid_credentials` → `"Неверный логин или пароль"`

**Преимущество:** Точное управление сообщением, независимо от HTTP статуса

---

### Вариант 3: С альтернативным полем кода
```json
{
  "error_code": "email_taken"
}
```
или
```json
{
  "key": "username_taken"
}
```
**Поддерживаемые поля для кода (в порядке приоритета):**
1. `code`
2. `error_code`
3. `key`

---

### Вариант 4: С текстовым сообщением
```json
{
  "message": "Email имеет неверный формат"
}
```
или
```json
{
  "detail": "Сервер временно недоступен"
}
```
**Сообщение пользователю:** Будет показано как есть

---

## 🔄 Приоритет обработки

Система определяет сообщение в следующем порядке:

1. **Код с бэкенда** (`data.code` / `data.error_code` / `data.key`)
   - Если найден в конфигурации → используется текст из конфигурации
   
2. **Маппинг по HTTP статусу** (`apiMessages[context].byStatus[status]`)
   - Если есть маппинг для данного статуса → используется он
   
3. **Текст из бэкенда** (`data.message` / `data.detail`)
   - Если есть строка → показывается как есть
   
4. **Дефолтные значения**
   - Для успеха (2xx): `defaultSuccess` → `cfg.success` → `'Операция выполнена успешно'`
   - Для ошибок: `defaultError` → `cfg.unknown_error` → `'Произошла ошибка'`

## 📚 Примеры для разных сценариев

### Логин

#### ✅ Успешный логин
```json
HTTP 200
{
  "user_type": "teacher",
  "access_token": "eyJhbGc...",
  "message": "Добро пожаловать!"
}
```

#### ❌ Неверный пароль
```json
HTTP 401
{
  "code": "invalid_credentials"
}
```

#### ❌ Пользователь заблокирован
```json
HTTP 403
{
  "code": "account_blocked",
  "message": "Ваш аккаунт заблокирован администратором"
}
```

---

### Регистрация

#### ✅ Успешная регистрация
```json
HTTP 201
{
  "user_id": 123,
  "username": "ivan",
  "message": "Регистрация успешна!"
}
```

#### ❌ Email уже занят
```json
HTTP 409
{
  "code": "email_taken"
}
```

#### ❌ Невалидные данные
```json
HTTP 400
{
  "message": "Email имеет неверный формат",
  "errors": {
    "email": ["Введите корректный email адрес"]
  }
}
```

## 🛠️ Доступные коды в конфигурации

### login
- `invalid_credentials` - "Неверный логин или пароль"
- `user_type_missing` - "Не удалось определить тип пользователя"
- `network_error` - "Нет связи с сервером"
- `unknown_error` - "Произошла ошибка при авторизации"

### register
- `email_taken` - "Пользователь с такой почтой уже существует"
- `username_taken` - "Такой пользователь уже существует"
- `unknown_error` - "Произошла ошибка при регистрации"

## ➕ Добавление новых кодов

Для добавления нового кода отредактируйте `src/api/apiMessages.js`:

```javascript
export const apiMessages = {
  login: {
    success: 'Вы успешно вошли в систему',
    invalid_credentials: 'Неверный логин или пароль',
    
    // ✅ Добавьте новый код здесь
    account_blocked: 'Ваш аккаунт заблокирован',
    password_expired: 'Срок действия пароля истёк',
    
    byStatus: {
      400: 'Некорректные данные',
      401: 'Неверный логин или пароль',
    },
  },
}
```

## 🔍 Отладка

В консоли браузера можно увидеть, какое сообщение было выбрано:

```
📝 [resolveApiMessage] Обработка ответа: {context: "login", status: 409, data: {...}}
✅ [resolveApiMessage] Найден код "email_taken": "Пользователь с такой почтой уже существует"
```

Это помогает понять, почему показывается то или иное сообщение.

## 📋 Рекомендации для бэкенда

1. **Используйте коды ошибок** (`code`) для типовых ситуаций
2. **Добавляйте `message`** для более детального описания
3. **Используйте правильные HTTP статусы**:
   - `200` - успех
   - `400` - невалидные данные
   - `401` - не авторизован
   - `403` - нет доступа
   - `409` - конфликт (email занят и т.д.)
   - `500` - ошибка сервера

4. **Пример идеального ответа с ошибкой:**
```json
HTTP 409
{
  "code": "email_taken",
  "message": "Пользователь с email ivan@example.com уже зарегистрирован",
  "field": "email"
}
```
